# Finland-s-energy-demand-forecast

# Прогнозирование потребления электроэнергии по погодным данным (Финляндия, 2015–2020)

Проект исследует, как погода определяет почасовое потребление электроэнергии в стране с холодным климатом и электрическим отоплением. На основе реальных данных финского системного оператора и климатического реанализа ERA5 построена модель, которая предсказывает нагрузку энергосистемы, используя **только погодные и календарные признаки** — без каких-либо сведений о предыдущем потреблении.

Финляндия выбрана как ближайший аналог Казахстана: та же зимняя пиковая нагрузка, тот же отопительный характер спроса — но, в отличие от Казахстана, с открытыми почасовыми данными.

## Датасет

Датасет **собран самостоятельно из двух первичных источников**, а не загружен готовым файлом.

### 1. Потребление электроэнергии

- **Источник:** [Open Power System Data — Time series](https://data.open-power-system-data.org/time_series/), файл `time_series_60min_singleindex.csv`
- **Первоисточник:** платформа прозрачности ENTSO-E, данные финского системного оператора
- **Столбец:** `FI_load_actual_entsoe_transparency` — фактическая измеренная национальная нагрузка, МВт
- **Период:** 2015-01-01 — 2020-09-30, шаг 1 час
- **Лицензия:** открытые данные, требуется указание источника

### 2. Погодные данные

- **Источник:** [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api) (реанализ ERA5, Copernicus/ECMWF)
- **Города:** Хельсинки, Тампере, Оулу — сведены в национальный ряд с весами по численности населения
- **Переменные:** температура воздуха на высоте 2 м, относительная влажность, скорость ветра, облачность
- **Особенность:** реанализ пространственно полон — пропущенных значений по построению нет
- **Лицензия:** CC BY 4.0, API-ключ не требуется

## Методология

1. **Сбор данных.** Загрузка почасовой нагрузки из OPSD и погодных данных через API Open-Meteo. Обе выгрузки приведены к единой временной оси UTC и объединены по метке времени.
2. **Описание данных.** Проверка размера, типов, пропущенных значений и — отдельно — пропущенных меток времени в индексе.
3. **Очистка.** Удаление дубликатов меток времени, отсев физически невозможных значений нагрузки, проверка выбросов по правилу межквартильного размаха.
4. **Генерация признаков.** Календарные признаки (час, день недели, месяц, выходные, праздники) построены по местному времени `Europe/Helsinki`; циклическое кодирование времени; градусо-часы отопления и охлаждения; лаг и скользящее среднее температуры.
5. **Разведочный анализ.** Семь групп визуализаций, каждая отвечает на конкретный исследовательский вопрос.
6. **Моделирование.** Задача регрессии. Разбиение **хронологическое**, а не случайное: обучение на 2015–2018, тест на 2019–2020.
7. **Модели.** Сезонная наивная базовая модель → линейная регрессия → случайный лес → случайный лес с подбором гиперпараметров через `GridSearchCV` с кросс-валидацией `TimeSeriesSplit`.
8. **Оценка.** RMSE, MAE, MAPE, R². Анализ важности признаков и структуры остатков.

### Обоснование ключевых решений

**Почему хронологическое разбиение?** Случайное разбиение поместило бы час *t+1* в обучающую выборку, а час *t* — в тестовую, то есть модель «подсматривала» бы в будущее. Для задачи прогнозирования это методологическая ошибка, завышающая оценку качества.

**Почему случайный лес?** Зависимость потребления от температуры нелинейна и взаимодействует со временем суток. Ансамбль деревьев улавливает и то, и другое без явного задания взаимодействий. Линейная регрессия сохранена как интерпретируемая базовая модель: её коэффициенты читаются напрямую в мегаваттах на градус.

## Ограничения

- **Ряд OPSD заканчивается в 2020 году**, поэтому модель не проверена на последних годах, включая европейский энергетический кризис 2022 года.
- **Погода представлена тремя городами.** Взвешивание по населению — приближение к реальному пространственному распределению нагрузки.
- **Авторегрессионные признаки не используются.** Добавление недавних значений потребления заметно повысило бы точность, но это ответ на другой вопрос: проект выясняет, какую долю потребления объясняет **только** погода.
- **Структурный сдвиг COVID-19** попадает в тестовый период и занижает измеренное качество модели. Он не удалён, а описан.
- **Ансамбль деревьев не умеет экстраполировать.** Температуры холоднее, чем встречались в обучающей выборке, будут предсказаны как самые холодные из наблюдавшихся — существенное ограничение для задач планирования мощности.
- **Данные не по Казахстану.** Финляндия использована как аналог; выводы о величинах не переносятся напрямую, переносится метод.

### Направления дальнейшей работы

- Расширить ряд напрямую через API платформы прозрачности ENTSO-E, которая обновляется и после 2020 года.
- Сравнить с градиентным бустингом (XGBoost, LightGBM, CatBoost).
- Добавить явные признаки взаимодействия «погода × час суток».
- **Повторить для Казахстана.** ERA5 покрывает Астану с тем же разрешением, что и Хельсинки, поэтому погодная половина пайплайна работает без изменений. Препятствие в другом: открытых почасовых данных о нагрузке казахстанской энергосистемы не публикуется. Эта асимметрия — свободно доступный климатический реанализ при недоступных национальных системных данных — и есть самый переносимый результат проекта.
